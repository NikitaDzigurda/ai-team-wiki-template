# Git и совместная работа

Это исходные рекомендации. Команда определяет ветки, формат сообщений, порядок ревью и права на push в своей wiki и `projects/<project>/conventions.md`.

- Сохраняйте настройки подписи и авторства, принятые в репозитории.
- Перед коммитом проверяйте состав изменений. Не включайте чужие подготовленные изменения.
- Для сообщений можно использовать `docs: ...`, `chore: ...` или `wiki(<project>): ...`.
- Коммит и push — отдельные действия. Выполняйте их в пределах задачи пользователя и политики команды.
- `wiki.py sync` создаёт локальный коммит файлов текущего проекта. Только `--push` отправляет его в `origin`.
- Общие изменения в `context/`, `standards/` и `scripts/` проверяются и коммитятся отдельно: `sync` их автоматически не включает.
- После изменения wiki закоммитьте новый указатель сабмодуля в потребляющем репозитории, когда будете сохранять изменения проекта.
- Если основная ветка защищена, используйте ветку и pull request по правилам команды. CLI не обходит защиту веток.
- При конфликте остановите синхронизацию и разрешите его вручную. Не используйте force-push для обхода конфликта.
