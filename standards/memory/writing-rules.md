# Правила записи памяти

Сохраняйте неочевидные факты, причины решений, ограничения интеграций, указания пользователя и результат работы, который поможет следующему участнику.

- Перед созданием записи выполните `wiki.py recall`. Обновляйте существующую запись вместо дублирования, меняйте `updated`.
- Указывайте источник факта: путь к коду, проверенную команду, ссылку на документ или решение пользователя.
- Предположения явно помечайте; не называйте их подтверждёнными требованиями или решениями.
- Запуск и тесты описывайте в `overview.md`, устройство модулей — в `architecture.md`, ловушки — в `gotchas.md`.
- Временное состояние задачи храните в спецификации или итоге сессии, а не в постоянной памяти.
- Не сохраняйте секреты, пароли, токены, персональные данные и сведения, которые пользователь попросил не записывать. Проверка типовых шаблонов секретов не заменяет просмотр diff.
- Проверяйте актуальность памяти по коду. Устаревшее исправляйте, заменённый ADR помечайте `superseded` и связывайте с новым.

## Совместная работа

Обновляйте wiki через `wiki.py update` перед работой. Автообновление SessionStart по умолчанию выключено; команда может включить его в `config.json`.

Каждый репозиторий пишет в свой `projects/<project>/`. Общие изменения контрактов отражайте в `context/` и связывайте с ADR. Не переписывайте подтверждённые требования без изменения их источника.

При конфликте автораздела `index.md` сохраните ручную часть и выполните `wiki.py reindex`. Остальные конфликты разрешайте по смыслу. После проверки синхронизируйте изменения в соответствии с [политикой Git](../global/git-commits.md).

Стиль описан в [docs-style.md](../global/docs-style.md).
