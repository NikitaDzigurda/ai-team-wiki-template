# Формат памяти

```text
projects/<project>/
├── index.md          # компактный обзор и автоматически собранные ссылки
├── overview.md       # назначение, запуск, окружение и проверки
├── architecture.md   # модули и потоки данных
├── conventions.md    # соглашения конкретного репозитория
├── gotchas.md        # симптом → причина → что делать
├── memory/           # один устойчивый факт на файл
├── decisions/        # ADR: NNNN-slug.md
├── specs/            # планы: YYYY-MM-DD-slug.md
└── sessions/         # итоги: YYYY-MM-DD-slug.md
```

Имя проекта задаёт установщик в `.agent-wiki.json`; его можно переопределить через `--project`. Имена и slug пишутся в kebab-case.

## Память

Каждая запись `memory/<slug>.md` начинается с плоского YAML frontmatter:

```yaml
---
name: example-fact
description: Краткое описание проверенного факта
type: fact
created: 2026-01-01
updated: 2026-01-01
---
```

Это пример формата. Даты записи подставляет CLI. В теле укажите факт, **Почему:** (источник и значение), **Как применять:**. Строковые значения с двоеточиями или переносами CLI экранирует.

| type | Назначение |
|---|---|
| `fact` | Проверенное неочевидное знание |
| `feedback` | Указание пользователя и его причина |
| `reference` | Ссылка на ресурс и когда его использовать |
| `context` | Цель, срок или ограничение |

## Остальные документы

| Каталог | Frontmatter | Содержание |
|---|---|---|
| `decisions/` | `status`, `date`, `description` | Контекст, решение, альтернативы, последствия |
| `specs/` | `status`, `date`, `description` | Зачем, объём, план, проверка |
| `sessions/` | `date`, `summary`, `agent` | Цель, сделано, находки, следующие шаги |

Статусы ADR: `proposed`, `accepted`, `superseded`, `rejected`. Новый ADR создаётся как `proposed`; `accepted` ставится после принятия решения.
Статусы планов: `draft`, `in-progress`, `done`, `dropped`.

## Индекс и ссылки

Верх `index.md` редактируется вручную. Между маркерами `auto:index:start/end` пишет `wiki.py reindex`. Детали открываются по необходимости; в начале сессии достаточно индексов и релевантных записей.

Ссылки внутри wiki относительные: `[обзор](overview.md)`. Пути к коду пишутся в бэктиках: `src/example.py`. Валидатор проверяет относительные ссылки на документы, но не наличие путей к коду и не фактическую точность текста.
